# Requirement impact analysis

1. Read `../../rules/source-of-truth.md` and `../../workflows/requirement-impact-analysis.md`.
2. Verify the source in `reference/SOURCE_REGISTER.md`; distinguish approved requirements from reference-only material.
3. Produce actor, trigger, preconditions, main/alternate/error flows, postconditions and business rules.
4. Map requirement IDs to modules, API, data, UI, security and tests.
5. Record conflicts or missing decisions instead of inventing behavior.
